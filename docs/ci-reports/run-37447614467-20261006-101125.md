## shader 资产健康度（画面为什么是黑的）

口径是**按材质实际引用数加权**，不是按文件个数 ——
一个被 59 个材质引用的 shader 和一个没人用的，重要性差 59 倍。

`Dummy 桩` 指只有 `//DummyShaderTextExporter` 骨架、
没有真实 HLSL 的 shader。它**会编译通过**（所以构建不报错），
但渲染结果是错的。

最重要的一条：**「渲不出东西的 shader」占材质引用数 70.8%
（109/154）** —— 含两类：
`//DummyShaderTextExporter` 标记的 86 次，
以及「无标记但只有 1 个 Pass」的 23 次。

其中 `Universal Render Pipeline/Lit` 被 **59 个材质**引用，
而它是**混合形态**：25 个属性（_BaseMap / _BaseColor /
_Smoothness / _Metallic ...）齐全、标记也在、HLSL 是桩 ——
**看着像「有内容」，实际渲不出任何东西。**
它是 PBR 标准 shader，一失效所有非 UI 物体都没了。

所以修复顺序是：**官方源码覆盖 → 多 Pass 重建 → LightMode 补 tag**。
LightMode 排在最后，因为这两类没有光照代码可接收 uniform，
先补tag 是白做。

**无记录** —— 这一节为空**不代表** shader 健康，
只代表检查没跑或没输出。

## LightMode（物体发黑不发光的最可能原因）

URP 把没有 `LightMode` tag 的 Pass 归为 `SRPDefaultUnlit`。
Pass 不会消失，但 **URP 只在 `UniversalForward` 里注入光照
uniform**（`\_MainLightPosition` / `_AdditionalLights*` /
`unity_LightData`）—— 落进 SRPDefaultUnlit 就是**没人赋值**，
漫反射与高光全退化为 0。

判据是「这个 shader 是否消费 URP 光照数据」（可从源码读出），
不是「Pass 数」也不是主观判断：不消费的那批（UI / 轮廓 / Blur /
TMP）本来是 unlit，挂了 `UniversalForward` 反而是行为改动。

**无记录** —— 这一节为空**不代表** LightMode 没问题，
只代表检查没跑或没输出。
